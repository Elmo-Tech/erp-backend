## Migration preflight, lock and rollback contract

- Preflight `SELECT EXISTS` finds any row where the strict tuple predicate `IS NOT TRUE`; throws `RuntimeException` and refuses to add CHECK. PostgreSQL transactional DDL preserves P0-03 constraint and all original rows on failure. **No automatic correction of historical accounting data**.
- `ALTER TABLE journal_lines ADD CONSTRAINT ... CHECK` checks all existing rows, sets new CHECK as `pg_constraint.convalidated=TRUE`, and requires an `ACCESS EXCLUSIVE` lock held until transaction commit. `SET LOCAL lock_timeout='3s'` bounds lock-acquisition waiting; `statement_timeout='30s'` bounds query runtime in disposable CI only. Production-like row volume/lock budget and concurrent write contention **NOT RUN / NOT VERIFIED**. Do not treat CI runtimes as production evidence.
- Rollback drops **only** `p004_fx_snapshot_complete_chk` and leaves P0-03 intact; original weak null semantics intentionally return on rollback. Reapplying without cleanup of synthetic bad historical rows must still fail closed.
- The constraint is independent of PHP validation, P0-04A row triggers and P0-04B advisory checker. No status mutation, real posting transition, API, RLS, grants or customer data.
