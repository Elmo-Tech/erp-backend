**Constraints added:** permissible company/membership/global grant/fiscal/period/ledger/journal status values; journal side XOR positive; currency amount and rate snapshot coherence; account type and normal side; line number; period/fiscal dates; posting timestamp consistency. PostgreSQL exclusion + `btree_gist` blocks overlapping fiscal years / accounting periods per legal company, with distinct EG and IT calendars independently allowed. Guard triggers enforce fiscal-year→period and period→journal date containment on child INSERT/UPDATE and parent boundary UPDATE. FK lookup indexes cover period, journal, entry and account. No posting, immutable GL, period-lock or balancing APIs introduced.

**Migration contract:** additive `2026_11_16_000006_harden_company_accounting_invariants.php`; PostgreSQL-only, checks validate existing rows on apply; extension `btree_gist` needs installer privilege; **existing production data NOT inspected and migration NOT approved for production**. Rollback drops P0-03 objects but preserves extension for shared dependencies. Independent upgrade/rollback/data cleanup review still required.

**RLS strategy:** experimental role `p003_rls_probe` is `NOLOGIN NOBYPASSRLS` with SELECT on `fiscal_years` ONLY, not users/journal_lines. RLS policy uses `NULLIF(current_setting('app.company_id',true),'')::uuid`. CI calls sandbox SQL `database/security/p003_rls_pilot.sql`: same connection with savepoints, fail closed on unset company, EG→IT and IT→EG, context rollback, and final ROLLBACK of role, rows and policy. **Role and RLS policy are NOT installed by Laravel migrations.** A client that can set arbitrary app.company_id could impersonate any tenant; authentication/authorization and controlled context setters remain mandatory. PgBouncer transaction pool, Octane/queue worker reuse, transaction boundaries, prepared statements, and concurrent cross-session tests are NOT VERIFIED. Never use session-level SET or trust a request-supplied company id.
